# 全局 Node 基线实施与验收

2026-09-30，用户确认执行 `lumine-node-runtime-execution`。本轮覆盖整个 Harness 与当前采用父工程的受管升级，Vue／Go 业务子仓只读；没有提交、推送或发布，也没有改系统 Node、业务引擎或用户 profile。

## 实施结果

- 统一策略支持 Node 22.x ≥22.18.0 或 24.x ≥24.11.0，推荐 Node 24 LTS；Node 18、20、其他主版本与预发布版明确拒绝。
- CLI、任务／工作状态、阅读服务、采用／升级／恢复工具和外部 Node Hook 使用薄入口，版本合格后才动态加载实现。内部实现和 vendor 以 Node 22 构建；低语法启动层仅用于拒绝诊断。
- Adapter 区分检查进程与宿主事件的实际 runtime。旧事件缺少实际进程记录仍未观察；Bun 的兼容 Node 字段不能证明 Node 或 Bun 支持。OpenCode 实现放在受管 Runtime 内，插件发现目录只保留入口。
- TypeScript 为唯一运行源码；规范 Skill 与 Plugin wrapper 同步。公开支持说明、中英文错误反馈及 Node 22 类型约束已更新。
- Kimi／ZCode 根标记识别、独立 dispatcher 的预检依赖打包，以及 macOS 符号链接下 CLI 主入口识别问题一并最小修复并验证。

## 实际版本和隔离分发

[版本矩阵](actual-node-matrix.json)记录 341 项操作、9 个安装／服务夹具。支持路径使用真实 Node 22.18.0、24.11.0、当前 24.14.0；22.18／24.11 分别覆盖独立 Skill 与 Plugin、Git 与非 Git 目标。运行不依赖源码仓或其 node_modules。

真实 Node 18.20.8、20.19.0、22.17.0 共执行 234 项双语拒绝检查，覆盖包装器、直接 mjs、Hook／dispatcher、维护 inspect／proposal／apply／resume／rollback／finalize。错误含实际版本、支持范围与升级动作，退出码为 2；目标及恢复材料的文件哈希保持不变。纯函数另外覆盖其他主版本与预发布版。

支持版本的隔离安装、续跑、finalize 和回滚通过。这里的 finalize 使用没有真实宿主要求的夹具，不能证明正式项目宿主调用。每个阅读服务的 117 个资产指纹一致，109 个公开静态文件可访问，8 个许可证文件保留。

## 浏览器阅读证据

[Node 22](browser-node22.json)与[Node 24](browser-node24.json)分别实际运行本地阅读服务，在无源码／开发依赖的 Plugin 夹具中阅读正文、查询 `architecture`，并检查 architecture、sequence、flow、state、ER 五类 Mermaid 的页内 SVG 与放大视图。

浏览器只允许两个指定回环服务，外部请求负对照被阻断；两个实际 Node 的 HTTP／HTTPS／fetch 负对照也被阻断。应用请求均为本地请求，没有应用 pageerror。这是请求隔离验证，不是物理断网，也不证明人类接受。路由关闭 HTTP 缓存；Node 24 搜索脚本首次在查询状态更新前断言，改为等待实际结果状态后通过，未修改阅读器实现。临时浏览器及两个服务已关闭。

[中文文件与稳定引用／服务生命周期补验](unicode-stable-lifecycle.json)在实际22.18／24.11分别完成中文相对路径、稳定ID和查询的CLI读取，配置／目录／正文HTTP核对及两次服务启停；重启后同ID可读。正文和7个Mermaid块不变，各17个已存在保护文件保持原哈希；空的基线／候选目录不被当成有既有材料的保护测试，其既有资产保护由安装矩阵和正式父仓指纹核对提供。初次端口检查被沙箱拒绝，使用已授权本机权限后通过，不计为Runtime失败。全部临时服务已关闭。

## 旧恢复工具

[旧工具记录](old-tool-recovery.json)核对保留维护入口与改动前生成资产的 SHA256 相同，并补齐与其匹配的迁移依赖和包入口。真实 Node 18.20.8 下，独立旧工具完成 inspect、提案、隔离采用与回滚，业务夹具不变、无恢复冲突。源仓快照在初期并行入口整理期间取得，不能当作全部源码的改动前副本。

恢复材料保存在受保护 local 目录及既有恢复事务内；它们未被清理或公开。验证只针对所保留版本与隔离事务，不承诺任意历史事务通用回滚，也没有对正式父仓执行回滚。

## 检查与验收范围

首次集成测试暴露共同 Hook helper 未进入选择性安装清单，以及静态测试仍定位旧 OpenCode 文件的问题，修复后源码与生成分发各 236 项：235 通过、1 跳过。实际版本矩阵另外暴露主入口符号链接识别问题，已修复并加实际别名回归。最终[静态定位器增量](config-launchers-actual.json)另有69项真实Node操作通过，含11入口在六个实际版本的支持／拒绝协议和3个中文负路径；fs与stdin负对照证明低版本在根读取前拒绝。3项持久专项测试通过，生成配置哈希与实测输入一致。最终[typecheck／build／check／测试／分发同步门禁](final-gates.json)全部通过，跳过项未计为通过。[独立收口审查](independent-closeout-review.json)明确区分完整22.18／24.11分发矩阵、当前24.14较窄smoke，以及POSIX配置执行与未验证宿主。

全局AC-runtime、AC-distribution和Repo Wiki AC-012在本执行计划中的版本、同源分发、阅读、稳定引用、服务生命周期与资产保护要求得到上述证据。请求隔离的边界仍按实测记录报告；原Wiki的其他AC、人类接受、真实父工程宿主及未实测社区宿主／Bun不因本轮检查升级为通过。原Node18阅读和迁移记录保留历史身份。

[父工程真实宿主缺口核对](parent-host-gap.json)确认已保存的35条真实事件与现有会话状态均早于最终提案应用；升级后可用事件／状态为0，原探针已过期，实际Hook进程尚未观察。入口文件哈希匹配不能替代这个证据。该检查没有创建Probe、人工调用Hook或伪造observedAt；只判断已保存材料，不推断未记录事件从未发生。

当前没有阶段授权问题。剩余正式目标动作是取得父工程新入口的真实SessionStart／Stop事件、匹配项目和会话的schemaVersion2材料及实际Node记录，再按最终受管事务执行finalize；宿主未验证前不把事务写为完成。
