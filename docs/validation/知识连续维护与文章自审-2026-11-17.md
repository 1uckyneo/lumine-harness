# 知识连续维护与文章自审

日期：2026-11-17。范围：当前规范 TypeScript、知识 Skill 和上游 Wiki 的定点整理。

这份记录分别说明自动回归和文章自审。没有调用目标日常模型进行写作测评，也没有以作者复读代替独立读者或用户接受。

## 连续六轮维护

新增 [连续演化测试](../../skills/lumine-harness/src/harness/tests/wiki-evolution.test.ts)，以脱敏的双仓“认证库与命令行”样本连续执行六次变化。候选由测试明确给定，不经过模型生成；测试目的为验证工具合同能支持正确维护并保护资产。

| 变化 | 实际检查 |
| --- | --- |
| 新增能力 | 从 `context` 取得关联机制和完整规范入口，通过 `prepare/apply` 将新页面、导航、覆盖一并保存；查询能够找到它。 |
| 机制改变 | `impact` 返回来源或主题命中及关联候选；原文档 ID、查询别名、条件与否定保留；非重叠人工纠正合并进正文，未混入生成基线。 |
| 跨模块变化 | 不同仓库来源同时命中调用方与被调用方；一组候选更新双方解释，缓存有效期变化不删除认证条件。 |
| 页面拆分 | 原文档保留身份与人工说明；旧章节显式迁到新专题，关系与导航一同生效；沿旧章节仍找到准确新位置。 |
| 规则修订 | 普通更新被规范保护拦截；对旧候选显式作保留当前决定后，以说明依据的规范变更重新准备；条件、否定和适用范围完整保留。 |
| 过时退出 | 历史页退出默认查询与影响候选，仍可按明确引用或历史搜索读取；旧来源和事实保留，不重定向到语义不同的新机制。 |

六轮均调用公开知识操作，成功写入后执行 `checkWiki`。结构检查仍明确不验证语义准确性、业务运行或人类接受。旧受保护候选不会因为另一个包成功就被静默删除；测试通过公开决定接口记录不采用的原因。

验证命令：

```bash
node --import tsx --test \
  skills/lumine-harness/src/harness/tests/wiki-evolution.test.ts \
  skills/lumine-harness/src/harness/tests/wiki-view-blocks.test.ts \
  skills/lumine-harness/src/harness/tests/wiki-context.test.ts
pnpm runtime:typecheck
```

结果：21 项测试通过，0 失败；其中连续演化为 6 个子测试加 1 个父测试。类型检查通过。另两组覆盖声明块保真、安全解析、上下文预算、CLI 路由、来源与展示关联检查、读缓存及事务恢复。原始终端输出和命令回执保存在已忽略的 `.cache/knowledge-evolution-review/`，不进入发行包。

## 上游文章的定点整理

通过同一个公开更新包修改以下四篇；随后为采用说明补充当前格式实现的准确来源。

- [Adapter 公共协议与各宿主差异](../repo-wiki/Adapter%20公共协议与各宿主差异.md)：先解释公共职责与宿主差异，将运行环境、读取证据的细节放入有明确标题的展开区。
- [Core、Skill、Adapter 与构建分发](../repo-wiki/Core、Skill、Adapter%20与构建分发.md)：先解释各层分工，再展开入口、清单和资源恢复；去掉把某一轮开发过程当长期正文的表达。
- [项目配置、根解析与多仓身份](../repo-wiki/项目配置、根解析与多仓身份.md)：删除正文中无阅读价值的内部来源 ID，保留来源关联；解释两类资源定位器的区别，再展开实现细节。
- [首次采用、升级与迁移恢复](../repo-wiki/首次采用、升级与迁移恢复.md)：拆开过长维护段落，并修正“后续始终保持 schema 3”的过期描述。存储格式保护与编排合同分别使用配置版本 3、4，产品工作流版本仍为 2；实现依据为 `wiki/compaction.ts`。

原有 32 个章节身份、全部 90 条来源关联和长期决定保留；采用说明另增加 1 条格式保护来源。新增展开区保留完整文字，可由查询与 Agent 读取。公开更新包为 `3905c298-8e08-45d4-b09c-19956e881052`，来源补充包为 `7839f478-b7e6-4ffa-be98-ed2f594ab35f`；更新后知识检查通过。

对这四篇记录的是 **Agent 作者自审**：核对说明顺序、稳定章节与来源、运行条件及恢复边界。细节分层不等于删除唯一知识，也不宣称其余所有历史文章已重新写作。

## 目前可以与不能据此得出的结论

自动回归证明工具能够支撑上述连续维护，不需要重跑采用流程；声明块、引用、规范保护和三方合并均有明确断言。写作指南、阅读意图和工作包能减少执行模型自行决定的事项。

这些结果仍不能证明某个较弱模型会正确调查、保持全部语义并写出合格文章。后续模型测评应让目标模型在无先前会话背景下完成相同变化，由另一位评审按已知条件、来源和读者问题核对候选。真实读者是否读得舒适，另依浏览器交互、视觉与阅读验收记录判断。
