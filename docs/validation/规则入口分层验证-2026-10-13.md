# 规则入口分层验证

## 请求与边界

2026-10-13，用户要求整理项目 AGENTS 的基础规范与技术细则，并修正 Lumine Harness 使后续采用项目避免重复问题；本轮明确授权实施、提交和推送。这是已有规则维护，不改变产品行为，不强制补一份产品方案或执行计划。

## 结果与规则去向

- 双语目标根模板只保留仓库和授权边界、安全底线、明确规范入口、必要阶段门禁与收尾协议。框架维护解释留在采用指导，技术细则、示例、知识和指南按职责各维护一份正文。
- 生成器移除重复地图、自链和伪项目规则；先应用配置 override，再按真实 Wiki 路径渲染，实际非空规范索引存在才声明附件，首页尚未建成则链接配置目录。
- 采用／升级在现有 Validation 记录每项旧规则的来源、适用范围、目标正文、效力、必读入口与处置理由；独有规则先迁后删，保留项目特殊授权。文件 preserve 只负责保护，不代替规则对齐和内容验收。
- Product Spec 维护产品方案的目标、范围、场景、规则和验收；Exec Plan 承接适用 Spec／AC 的技术方案、取舍、安排、进度及执行记录；Validation 留原始证据，Wiki 分清规范、示例、长期约定与实现。
- 完整内置 grilling/domain-modeling 模块及来源未变，提问写回与阶段确认仍由共享 Skill 指导，不复制到根入口。
- 试点将原根独有 Go 测试规范迁回后端规范，保留插件编辑前门禁；修复过期登录摘要与同系统工作分支规则。项目既有服务扩展安装授权字节不变，其他会话的业务文档与任务保持原内容。
