# Repo Wiki 受限存储与剪贴板回归

日期：2026-09-30（Asia/Shanghai）。在源仓本地只读服务 `127.0.0.1:4331` 上，用独立 Chromium 标签验证 AC-011 中的浏览器权限受限路径。浏览器预加载脚本使 `window.sessionStorage` getter 抛出 `SecurityError`，使 `navigator.clipboard.writeText` 拒绝并抛出 `NotAllowedError`，随后重载页面。此注入只作用于该测试标签，不修改项目或浏览器的持久配置。

| 场景 | 实际观察 |
|---|---|
| 直接打开 `?doc=lumine-wiki-reader` | 标题“知识树、图解与来源阅读”、正文、目录、来源入口和 Mermaid 图均显示；页面未停在 Loading。 |
| 搜索 `reader` | URL 更新为 `?search=1&q=reader`；显示 3/3 项结果，含正文与章节命中。 |
| 点击“复制引用” | 显示“剪贴板不可用，请从打开的文本窗口手动复制。”；对话框内可选中的 `<pre>` 内容为 `lumine-wiki-reader`。首次实测发现弹窗错误沿用“查看原始 Markdown”标题，现已改为“手动复制文本”；重新构建和重载后复测通过。 |

规范源码的中英文标题分别为“手动复制文本”和“Copy text manually”；按钮原有的“查看原始 Markdown”文案仍用于真正的 Markdown 内容。受限存储时，语言、筛选、目录展开、最近阅读及滚动位置无法跨刷新保留；当前会话内的正文与搜索可用。升级后的父仓同一受限 Chromium 标签切换为英文界面后，点击 “Copy reference” 显示 “Copy text manually” 和英文失败提示，文本仍为 `workspace-system-boundaries`；中文正文没有被翻译或隐藏。旧静态 chunk 与项目重命名组合场景另见单独记录或仍待验证。

修订后 `pnpm runtime:typecheck`、`pnpm runtime:build`、`pnpm runtime:check`、`pnpm runtime:test:source`、`pnpm runtime:test`、Skill 包检查、Plugin wrapper 同步与仓库同步检查通过。源码和分发测试各 222 项、221 通过、1 项既有跳过。测试需要监听本机回环端口；受限沙箱首次运行因 `listen EPERM` 失败，按工具权限流程重跑后通过，不记作代码通过前的功能失败。随后用同一受限 Chromium 标签打开已升级的父仓 Node 18 服务，长文“三仓职责与系统运行边界”正常显示；复制引用弹窗标题为“手动复制文本”，内容为 `workspace-system-boundaries`，无页面脚本异常。上述证据只证明本机当前构建与此场景的浏览器行为，不证明目标宿主加载或读者接受。
