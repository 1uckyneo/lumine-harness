日期：2026-09-30。依据[本轮 Spec](../../../product-specs/Repo%20Wiki%20知识体系与%20React%20阅读体验.md)的 AC-001～AC-014 和[预先固定的问题与判据](M0%20问题与判据.md)，分别核对 Lumine Harness 源仓与 `ai-conv-plus-workspace` 父仓。Vue／Go 业务子仓仅作为只读来源。本记录把源码及夹具、真实本机服务、独立静态复评、普通读者接受和部署分开；「局部验证」不等于整个 AC 通过。

## 已完成的可核实范围

- **知识和迁移。** 源仓 8/8、父仓 29/29 篇 Wiki 已逐篇转为简短页首和同文件文末结构化声明。转换前后比较正文、解析模型、生成基线、来源观察与审阅时间；旧部分工作包及候选以明确的 `keep-current` 保留，格式变化不冒充语义更新。源仓记录见[源仓格式核对](m3-source-format-final.json)和[受保护更新](源仓知识复评与事务.md)，父仓见[父仓格式核对](m4-target-format.json)及其 `docs/validation/lumine-wiki-react/2026-09-30/父仓技术验收.md`。恢复副本及起点哈希见[M0 基线](M0%20基线与恢复.md)。
- **实现和分发。** React＋TypeScript 阅读器、可分页的浏览器搜索、保留六卡及字符预算的 Agent 查询、来源分类处置、任务知识同步合同、项目身份隔离已进入规范源码及生成资产。`pnpm runtime:typecheck`、`runtime:build`、`runtime:check`、`runtime:test:source`、`runtime:test`、Skill 包检查、Plugin wrapper 同步与仓库同步检查通过；最终源码及分发测试各 223 项、222 通过、1 项既有跳过，构建与浏览器恢复专项 6/6。`git diff --check` 无报错。这些门禁证明对应源码、产物和夹具，不替代目标宿主或普通读者的结果。
- **本机服务和阅读。** 源仓与父仓的本地 Chromium 阅读检查覆盖首页、长文、章节、深链、搜索续页、来源面板、Mermaid、中文/英文 UI、390px 无水平溢出及 200% 缩放；桌面与窄屏留有[父仓长文截图](目标父仓桌面长文.png)和[源仓窄屏截图](源仓窄屏长文.png)。[最终交互回归](Chromium%20最终交互回归.md)另验证导航焦点、文档 B 加载失败时旧正文清空、重试恢复、窄屏目录收合，以及父仓修订后的图解在桌面和手机中渲染与放大。[同端口回归](同端口项目切换与恢复.md)补验同一标签顺序切换两个项目、服务断开重启、按项目语言显示切换提示。390px 内嵌宽图文字较小，细读需使用放大层。父仓受管资产又在 Node 18.20.8、根目录无开发 `node_modules` 条件下冷启动；首页、静态资产、配置、目录、长文与分页 API 均返回 200，目录 35 个可读文档，目标长文 2 幅图、10 个来源，搜索首批 20/26 且可继续。HTTP 与截图仅证明本机相应路径。
- **权限与旧资源。** [受限存储和剪贴板回归](受限存储与剪贴板回归.md)在源仓验证长文、搜索 3/3、复制失败提示和可选中文本，父仓同一受限 Chromium 标签也打开长文并显示准确的手动复制内容。[旧入口与资源切换回归](旧入口与资源切换回归.md)使用父仓升级前真实 `reader.js` 注入新版 Node 18 服务，正文和 Mermaid SVG 加载，所请求旧 chunk 均返回 200；构建与安装器夹具验证保留旧资源及许可、先写依赖再切换入口。
- **旧引用与动态图解恢复。** [补验记录](旧引用与图解恢复回归.md)保存旧深链失败、API 默认合同、真实重命名操作和旧章节映射：旧 ID／路径／同页片段均规范到当前引用，后退和刷新保留章节焦点。响应拦截分别模拟 Mermaid 主模块和图种模块 404，正文／源码保留，中英文及放大层整页重载后图解恢复；父仓 Node 18 同路径也通过。独立临时项目另实际升级／回滚：新增受管 chunk 删除后，新入口延迟加载得到 404，重载旧入口后恢复 SVG 及深链接；临时版本只改变主模块路径，未据此推定任意历史版本兼容。
- **搜索、五类图解与无外网冷启动。** [增量记录](搜索、五类图解与无外网冷启动.md)保存双语筛选/范围/零结果、Spec/Plan 身份、1024px、五类图解与14个导出、真实剪贴板成功/拒绝及隔离 Plugin 冷启动。图解前方异步布局变化的定位缺口已修复，读者滚动后停止自动定位；初始失败与稳定后结果分别保留。各观察对应的构建版本、隔离夹具与请求防护边界写在记录中。
- **问题驱动复评。** 未参与撰写相关 Wiki 的 Agent 先按固定问题读 Wiki 作答，再对照当前源码。[首次答案](知识复评首轮.md)保留源仓根解析、未引用文件、浏览器超过六条搜索及父仓图片任务条件的不足。源仓按来源完成受保护修订。父仓另记录第一次遗漏取消竞态、第二次能从文字答出但发现流程图仍有歧义，继而用工作包 `e26d311e-9c05-44ea-b1c4-817958384e23` 修订两页图文。第三次独立复评先仅据最终 Wiki 作答，再核对 Vue/Go 源码，确认图单独阅读也区分接口成功与真实取消终态；父仓 `wiki check` 29 篇通过。Go/Vue 取消竞争属于静态源码推断，尚无运行复现。
- **任务知识同步。** 本轮源仓任务已用 CAS 升为 v3，`knowledge.sync` 记录 9 个知识处置决定（7 篇 Wiki 修订、目录范围修订与来源处置记录创建）、当前知识版本和限定核实范围；当前 scoped passed evidence 指向旧引用与动态图解恢复补验及搜索、图解与冷启动记录；AC-008 另绑定其完整搜索判据；较早的权限、旧入口及同端口证据仍在各自验证文档，不冒充当前阅读器代码指纹。`task check` 仅剩 13 条 `AC_NOT_VERIFIED`，没有知识或证据合同错误；这表示任务证据结构成立，除 AC-008 外的 13 项 AC 尚未被整体标为通过。
