# Repo Wiki 同端口项目切换与恢复回归

日期：2026-09-30（Asia/Shanghai）。在同一 Chromium 标签和 Playwright CLI 会话中，按顺序用源仓、`ai-conv-plus-workspace` 父仓的本地只读服务占用 `127.0.0.1:4330`。每次只通过本轮保存的前台进程句柄停止服务，确认退出后才让另一项目使用端口；未启动业务子仓服务。浏览器使用已缓存的 Playwright CLI，本轮没有下载浏览器依赖。

## 项目身份与位置

1. 源仓打开 `?doc=lumine-wiki-reader#reading-navigation`，标题为“知识树、图解与来源阅读 · Lumine Harness”，滚动位置 `428`，浏览器 `lumine:active-project` 为源仓 ID `a392df2c-e0f5-46d1-ab66-fa1107e3d106`；最近文档、滚动和目录状态均存于该 ID 下的键。
2. 停止源仓服务，在同端口启动父仓，保持原标签及深链并刷新。稳定状态转为父仓 `/` 首页，标题为“项目首页 · AI 对话工作区”，主标题为父仓名称、滚动位置 `0`，`lumine:active-project` 为父仓 ID `0a2b1de4-d97b-4246-b82c-a3320d2e47b7`。旧源仓文档没有出现在父仓正文。旧项目的 sessionStorage 键仍按旧 ID 保留，不能声称已物理清除；它们未作为父仓状态读取。
3. 父仓打开 `?doc=workspace-system-boundaries` 并滚动到 `600`，同项目的保存键记录 `600`。停止父仓服务后点击页顶“刷新”，页面仍显示该文正文和 URL，并出现“连接失败，已读内容仍可查看。请检查阅读服务后重试。”及“重试”按钮。点击页顶按钮会把浏览器滚动到页首，因此本步骤不把滚动值当作断连恢复的验证结论。父仓在同端口重启后点击“重试”，错误提示消失，仍显示父仓文档和原项目 ID。断连时浏览器控制台出现 3 条预期的请求失败错误。

## 文案与语言修订

初次切换时，原提示声称“已清除上个项目的临时状态”，与按项目保留的 sessionStorage 键不符。规范源码 `src/browser/reader-common.ts` 已将中英文提示改为“阅读服务已切换项目，现已返回当前项目首页。”及对应英文，不再声称清除。`reader.tsx` 在确定新项目保存的界面语言后生成提示，避免英文界面出现中文切换提示。

源码经 `pnpm runtime:typecheck`、`runtime:build`、`runtime:check`、`runtime:test:source`、`runtime:test`、Skill 包及 Plugin 同步检查；两个测试集各为 221 项、220 通过、1 项既有跳过。`lumine-wiki-reader` 用受保护工作包 `26c3274a-382e-40c4-87be-9b0bf38300f6`、`487a3c09-273c-44b8-b4b7-fb56b68b3606` 保持正文不变并更新来源观察；扫描恢复 `current`。

父仓先后用安装器提案 `0130b13d-d0c4-43ec-a312-2efa97ee0014`、`8cba1f31-1d10-4812-8c73-5ecd2a3b0c26` 同步受管阅读器。两次提案均为 198 项：190 `write`、8 `preserve`；实际内容变化仅在 `reader.js`、阅读器清单和安装元数据，未写 Wiki 正文或业务子仓。最新版 `reader.js` 与源仓分发资产 SHA-256 相等，父仓最新迁移 ID 为 `8cba1f31-1d10-4812-8c73-5ecd2a3b0c26`。这两个提案和初次升级提案仍为 `awaiting_host_verification`，不能用本机浏览器或 CLI 充当真实宿主后验收据。

最新版父仓又用 Node 18.20.8 冷启动：`/`、`/reader.js`、`/api/config`、`/api/catalog` 均返回 200，响应中的项目 ID 为父仓，阅读器脚本含新英文提示；同一 Node 18 运行时的 `wiki check` 为 `passed`、检查 29 篇，仍报告两条既有的知识状态警告。服务在检查后由原进程句柄停止。

修订后的同端口浏览器复测中，源仓接管父仓标签时回源仓首页并显示准确中文提示；父仓重新接管时回父仓首页并显示相同中文提示。把父仓界面设为英文后，浏览器存储中该项目的 `ui-locale=en`；切到源仓再切回父仓，父仓首页与切换提示均显示英文：“The reader switched projects and returned to this project’s home page.” 原项目正文和阅读位置没有混入。

## 边界

本轮补足 AC-011 的**同端口两项目顺序切换、服务断开及重试**样本，并核对 AC-014 的这一条双语提示。旧静态 chunk、存储或剪贴板受限、重命名映射等组合场景仍未逐项实测；本机回归不证明目标 Codex 宿主已加载新资产，也不证明普通读者接受。
