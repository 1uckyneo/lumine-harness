# 旧引用定位与图解资源失败恢复

日期：2026-09-30（Asia/Shanghai）。本次继续已确认的 Run，补验 AC-011 的文档／章节映射及动态图解资源失败恢复。源码、隔离夹具、本机浏览器和父仓安装器状态分别记录，不将本机结果写成目标宿主或人类接受。

## 问题与修订

原后端能通过 `document-aliases.json` 解析旧文档和旧章节，但浏览器只提交文档部分并用 URL 中旧 ID 判断正文身份。旧章节跨文档映射会停留在旧页；旧文档 ID 指向新 ID 时可能请求成功却不显示正文。

`/api/document` 新增显式 `full=1` 模式，浏览器分别提交 `id`、`fragment`，服务解析精确章节映射后返回完整正文与 `canonicalReference`。默认 API 保留原来的章节／图解 `selection` 和无效片段非成功响应；源码测试另覆盖浏览器实际使用的独立参数形态。新浏览器遇到尚无该字段的旧服务仍能取得全文并按返回身份处理。规范 URL 使用 `replaceState`，不额外插入别名历史项；同页旧片段也可进入解析路径。正文 revision 未变时不重建 DOM，内容或语言确有变化时重新定位，取消过期的章节定位帧。

Mermaid 主模块或图种动态模块载入失败时保留说明及源码，并提供中英文的整页“重新载入阅读器”入口。该操作重新取得当前入口和资源；顶栏“刷新”仍只读取项目数据。错误或超限图继续使用原有图解错误反馈，避免误导为资源加载问题。内嵌图容器和放大层保留按钮的可访问性。

浏览器恢复专项测试位于 `scripts/reader-diagram-recovery.test.ts`，独立执行，不进入 Node Runtime 构建。构建清单仍是 86 个 Runtime 文件，没有因测试引入 React／Mermaid 的 Node 依赖副本。

## 动态图解故障与恢复

隔离 Chromium 上分别让 `mermaid.core-*.js` 和 `flowDiagram-*.js` 返回 404，再打开源仓 `lumine-wiki`。两种故障均显示资源失败说明和整页重新载入按钮；正文标题与原始 Mermaid 文本保留。解除响应拦截后点击按钮，首幅图恢复为 SVG，当前引用 URL 保持，均无页面脚本异常。

另切换英文，内嵌图及放大层都显示英文资源失败说明和 `Reload reader`；放大层内按钮能完成整页重载，随后 SVG 恢复，当前引用及保存的英文界面保持。

父仓受管补丁应用后，用 Node 18.20.8 启动本地只读服务，在 `workspace-system-boundaries` 上同样拦截 Mermaid 主模块。失败时“三仓职责与系统运行边界”正文可读、252 字符图源码保留；解除故障并重新载入后生成 SVG，URL 保持，无页面脚本异常。
