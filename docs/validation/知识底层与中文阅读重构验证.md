## 独立发布审查与修正

独立审查先重读源码，再用合成夹具复现；审查与实现分开。发现并修复了以下问题：

| 发现 | 修正及复核 |
| --- | --- |
| 一次读取固定了空事务列表，期间开始的新事务可能暴露半完成正文 | 操作前后核对事务版本，发生变化丢弃整轮结果并有界重读；持续竞争明确失败，读取范围内禁止写入。并发开始、完成和瞬时错误回归通过。 |
| 关联列表先截断至12条，靠后的规范入口随之消失 | 先用完整关联集合确定必读规范，再限制展示条数；预算缩减仍保留规范入口，无法容纳时明确失败。 |
| 合法来源超过高亮字符上限时，整个来源接口失败 | 高亮作为可选增强；110KB已登记来源仍返回原文、行号和指纹，省略高亮结果。 |
| 已知旧版完成回执被误判为未知事务格式 | 增加严格的旧回执分支，未知格式继续拒绝；文件同大小替换也使缓存失效。 |

独立审查执行了3项正文／高亮保真检查及6项问题复核，9项均通过。随后新增的改名中断回归确认：持久步骤1或2中断时仍只显示完整旧页，恢复后只显示新页。并发和中断检查不再仅依赖“写完之后再读”的串行场景。

实际 Chrome 中的隔离检查确认：解释器不能读取宿主DOM、localStorage或宿主API，不能向第二个本地来源发请求；尝试自导航也被父页面的 `frame-src` 拦截，目标服务收到零请求。字体仅通过经清单和内容哈希校验的本地WOFF2白名单开放，未因此开放业务API或任意文件。此结果针对受控解释器与所测浏览器，不是任意第三方网页的安全承诺。

独立阅读沿首页、阅读器说明和知识影响文章，能够复述“先从来源找直接候选，再沿关系检查一层；候选仍需核实”。审查建议已将知识影响文章接入首页“纠正知识”的直接阅读路径。声明式块在浏览器中提供解释组件，原始Markdown仍会显示其配置文本；不宣称Git托管页面与阅读器具有同等排版。

## 无前文背景的实际维护试验

另建无Git的脱敏SDK／CLI样本，由没有本轮实现背景的Agent只读取样本资料、安装后的Skill和公开CLI进行维护，不向其提供测试答案或要求读取Runtime内部实现。样本把“每次直接取页、没有缓存”和“任何错误无限重试”两项旧说明与新的鉴权、短时缓存及有限重试实现并置，并包含人工补充与独立规范。

维护Agent经过调查、`prepare`、候选和`apply`更新首页、分页读取、命令行三页，保留稳定ID、章节、源码及规范。首次分页候选与人工追加位置冲突，流程保留冲突并返回部分成功；作者调整解释位置后重用同包，三方合并保留人工句子。最终人工编号说明在正文中为一份、生成基线中为零份，没有以当前人工正文替代生成基线。

初始样本有一处搭建错误：人工句被放在末尾元数据之后。工具明确拒绝，搭建者将同一句移回正文，随后继续；这不是模型修好了初始格式，也不计作产品语义成绩。并发尝试可变操作曾返回锁占用，后续串行执行，没有删锁或强制覆盖。

独立审查先从两份源码和规范形成行为判断，发现第一稿遗漏了日志回调的异常边界：日志回调若在错误处理过程中同步抛错，执行立即停止并传播日志错误，并不会继续重试或返回原读取错误。作者通过第二个公开工作包同步修正摘要、正文、流程图和图注，并说明异步日志Promise不被等待。最终12组独立本地替身断言通过，涵盖鉴权、缓存键和时间边界、权限拒绝、有限重试、编号字符串及日志异常。

最终 `wiki check` 为passed、导航问题为零；完整安全规范仍在 `requiredReading` 中且 `readFull:true`。规范页仍有 `KNOWLEDGE_STALE` 警告，主题覆盖也保留此前未映射提示；未为消除提示改写规范或重置基线。结构通过、作者审阅、独立源码核查分别记录，没有把它们写成所有页面都已current。

这次试验证明给定样本中工作方法可以执行，工具能够保护人工知识，独立审查能促成具体修正。它也显示首轮生成可能遗漏注入回调的条件。试验未测特定较弱模型、真实SDK用户、真实远端、完整导出、部署或真人阅读，不支持“换任意模型仍保证同等质量”的结论。

## 边界与尚未证明的事项

- 没有特定日常模型、真实SDK用户、独立真人或长期使用数据，不能声称任意模型的输出质量已被保证。
- Codex／Trae协议回归与真实宿主观察分开；真实Trae会话未获得，不补造完成回执。
- 按用户要求不安排Windows实机或专项验证。
- 历史生成资产与恢复备份分别统计；字体、许可证和阅读器资源增长不计作Wiki正文增长。
- 上游不携带业务项目的源码、文档、私有配置或本机绝对路径；公开测试使用合成样本。
