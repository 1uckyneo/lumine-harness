# Lumine 流程与文本知识体验

## 为什么要改

人和 Agent 应当用更少的重复说明推进需求，在换会话、换机器后恢复有效进度，并依靠源码、测试和运行证据判断结果。仓库知识要能解释真实机制、取舍和边界，便于人阅读，也适合纯文本模型使用。

本次覆盖 Lumine Harness 源仓及当前多仓项目：流程、四个日常 Skill、中英文资源、Runtime、构建分发、独立迁移、活跃任务、八个真实 Wiki 专题和本地阅读页。两个业务子仓只读；不自动提交、推送或发布。用户已在实施请求中批准整体方向和实施范围，迁移不重新制造机械确认手续。

## 使用方式

需求直接进入 Product Spec，必要时补设计与可行性验证，Exec Plan 负责技术方案与实施记录。功能任务默认保留两者，但只讨论产品时可以仅有 Spec。不改变行为契约、没有新产品决策且不需跨任务协调的局部修复可直接处理。已有授权在能力切换后持续有效。

四个日常入口分别是需求与方案规划 lumine-plan、实施与验证 lumine-run、知识维护 lumine-knowledge、视觉与交互设计 lumine-design。安装维护仍叫 lumine-harness。用户以自然语言提出目标，不必学习固定调用顺序。

## 全局 Node 支持政策（已确认，待实施）

2026-09-30，用户在澄清调整对象为整个 Lumine Harness 后，对已展示的全局支持政策回复“确认”。本次产品变更覆盖公共 Runtime、日常 CLI、安装升级与独立迁移、全部 Adapter 及独立 Skill／Plugin 分发。它是新的产品要求，当前 Node18 实现与历史证据尚未因此改变；技术实施见[Node 支持基线调整计划](../exec-plans/active/Lumine%20Harness%20Node%20支持基线调整.md)。

- 推荐 Node 24 LTS；正式支持 Node 22.x 的 22.18.0 及以上版本、Node 24.x 的 24.11.0 及以上 LTS 版本。维护工具使用同一版本范围。其他大版本、预发布版和未来 LTS 不自动取得支持承诺，加入前重新验证。
- 取消 Node 18／20 的支持承诺。Node 专用入口在执行操作或写入前拒绝不支持的实际运行版本，说明当前版本、支持范围与如何换用合格运行环境。中文、英文和机器可读调用都能准确识别原因。
- 检查对象是实际运行 Harness 的进程。Hook 所在宿主与维护终端的 PATH 可能不同，终端检查通过不能替代宿主就绪；公共 Core 的嵌入运行时按所需 API 和独立证据判断，不能只按 Bun 的 Node 兼容版本号拒绝或宣称通过。
- 采用工程的业务 package.json、.nvmrc、依赖、分支与用户运行环境不自动修改。缺少合格 Node 时给出反馈，不静默安装或切换用户环境。
- 自包含分发、纯文本知识、路径与只读保护、许可、人工修改保护以及独立恢复材料保留。低版本拒绝不能删除旧工具、备份或恢复入口；旧版本证据保留为其原有范围，不充当新版本验收。

## 验收合同

### AC-workflow 减少重复与正确授权

Spec 完整维护问题、目标、场景、规则、范围与验收；Plan 维护技术方案、取舍、顺序、进度、证据与恢复。独立 Draft 与固定六份导航文档退出日常流程。技术架构不误入视觉设计，已有批准设计可复用，附件按需选择；Skill 切换不重复确认。产品行为与验收变化要判断影响，局部技术调整不机械退回规划。

### AC-task 任务、证据与完成判断

需求及验收有稳定 ID，一个 Spec 可绑定多个 Plan，单项变化仅影响引用它的任务。内容指纹提示变化但不等于批准，排版、标题、文件名变化不能产生重复批准。历史批准与证据仅保留有依据的适用范围。检查区分通过、失败、不适用和未验证，包含目标、范围、证据及修复建议。仅验证或诊断可报告失败后结束，不自动修复。六种 WORK_STATUS 语义保留；讨论、实现、运行及部署分别判断，全项目检查显式调用。

### AC-skills 四个纯净日常入口

只安装四个新日常 Skill，正文简短、程序按需读取；参考资料不被发现为额外 Skill。不保留旧别名、旧目录教程或转发 Skill。检查由 Runtime 与相应语义判断承担，不新增第五个 check Skill。业务 Skills 与项目约束保留。规划及实施在新目标、实质范围变化和恢复时检索知识，记录实际使用引用；查询不自动全量改写。

### AC-locale 中文与英文体验

初始化支持 zh-CN/en，显式优先，其次项目配置；非交互首次无配置默认英文，并在提案显示。语言在指纹前确定，应用时不重新选择。选定语言覆盖引导、文档、模板、Skill 正文和参考、检查与阅读页；目标项目只安装一个语言版本的规范 Skill。临时答复语言不改配置，永久切换保护人工与历史。两种语言共用行为与测试，界面切语言不翻译正文或隐藏异语内容。

### AC-identity 中文文件名与稳定引用

支持中文、英文、混合和空格名称，不要求英文 slug 或拼音。身份、标题、路径独立，CLI 支持 ID、路径及无歧义名称，同名列候选。处理 Unicode 等价、大小写和非法文件名。文档、验收、重要章节、图和来源有稳定身份；重命名更新当前引用，用通用映射保持定位，不创建兼容占位页，不把历史锚点指到无关章节。

### AC-knowledge 有来源的工程知识

默认正文根 docs/repo-wiki，可显式配置一个其他根。知识按总览、专题和细节组织，覆盖架构、机制、现行方案、理由、约束及限制。来源使用仓库 ID 与相对路径、版本和指纹；推断明确标注，当前实现与拟议方案及部署状态区分。工程约定引用有效规则，知识排名不改变强制约束。两个项目各四个真实专题，每项目六个问题核对答案、范围与来源。

### AC-text 纯文本知识生产

Markdown 和 Mermaid 是唯一正文与图源码；卡片为可选中、搜索、复制的 HTML 文本。创建、维护、查询和语义核实不调用图像模型、不截图给模型、不产出封面、缩略图或持久 SVG。浏览器即时 SVG DOM 用于显示，Agent 只读文本及结构化数据；图像验证证据仍按独立用途保留。每次正常知识更新不产生图像文件。没有浏览器或视觉模型仍能完成知识工作。

### AC-reader 阅读与图查看器

离线阅读器支持目录、卡片/列表、正文、来源、关联知识和 Spec/Plan，搜索与仓库/类型/时效筛选，恢复阅读位置、键盘及异步反馈。阅读器面向桌面，保留 1440px 桌面窗口及桌面浏览器 200% 缩放下的可读性与操作；窄屏和移动设备使用场景不在支持与交付目标内（2026-10-08 用户确认调整）。Mermaid 支持架构流程、时序、状态及 ER；每图有稳定身份、标题、说明和来源。可打开、放大缩小、平移、适合窗口、重置、复制引用及源码，默认文本导出。主动 SVG 导出仅浏览器本地执行，去除脚本、远程资源、绝对路径和临时地址，保留图名、状态和版本。失败图不阻塞文字及其他图，超大图明确拒绝而不截断误导。

### AC-update 增量维护与人工保护

精确引用与监控范围同时覆盖新增、删除、改名、未提交及跨仓变化，未归属新文件登记待分类。准备与应用间重新核对来源、正文和配置，漂移保留候选。基线保存真实全文，三方合并只自动接受无冲突部分；无基线内容受保护。正文与持久状态一致提交，可中断恢复和并发保护；每单元独立报告结果。人工决定、有效候选、冲突及恢复材料不作为可随意删除缓存。

### AC-cold 持久状态与冷启动

.lumine/wiki-state 纳入 Git 且升级不覆盖；.lumine/local/wiki 默认忽略、仅存可重建文本缓存与本机状态。“重新调用模型”不等于无损重建。全新 clone 无缓存、不调用模型仍可阅读、检索并浏览器绘图；源码尚未取得仍可读知识，但不能显示来源已核实最新。清缓存、换工作树不丢人工保护与有效候选。

### AC-migrate 干净且可恢复的转换

旧格式只在独立迁移模块及测试处理。预检、暂存、应用、验证、宿主切换、清理、完成逐步记录，提案含项目身份、语言、版本、操作和前后哈希。写前备份，原子替换，续跑只接受原状态或本次输出；回滚不覆盖后续修改。旧私有资料、历史及唯一恢复材料保留且忽略规则继续有效。实际新入口证据取得后清理临时旧 Hook；宿主未刷新不能报完成。迁移器与备份在被替换 Runtime 外，多仓不假设原子性。

### AC-distribution 自包含与安全边界

TypeScript 唯一 Runtime 源码，生成 mjs；Plugin wrapper 同步生成。日常 Runtime、浏览器、迁移工具分离；服务端 Runtime 不引入浏览器绘图依赖，运行支持范围遵循全局 Node 支持政策。分发含搜索、Markdown、Mermaid、chunk、样式、必要图标与许可证，不依赖 CDN、外部字体、源码仓或其 node_modules。所有文件入口共用登记根及真实路径校验；只读回环服务拒绝异常 Host/Origin、跨域、写入、越界和符号链接逃逸，图解使用严格限制。

### AC-runtime 全局运行环境与版本反馈

公共 CLI、采用／升级／续跑／回滚工具和外部 Node Hook 使用一致的支持范围。以实际 Node 22.18.0 和 Node 24.11.0／当前24 LTS验证支持路径，以 Node18、Node20及22.18之前的22版本验证明确拒绝；拒绝前后目标业务文件、知识状态、安装元数据与用户配置不变。包装器、直接 mjs 调用和 Hook 启动均覆盖，不能用 package.json engines 或模拟版本字符串替代全部实际执行证据。

Adapter 就绪结果区分实际运行环境、配置与真实宿主执行；终端合格、宿主旧 Node 的场景不得误报就绪。嵌入公共 Core 的宿主按其实际运行时单独检验，未取得真实运行证据则保留未验证。中英文支持说明、错误反馈、规范构建与两种分发保持一致；API 使用不高于最低支持版本的实际能力。旧恢复材料及其适用工具可保留使用，升级拒绝不导致无法恢复。

### AC-migration-content 两项目内容与历史保护

源仓保留维护者规则与规范源码自用方式；当前项目保留三仓 Git、Go 只读、文案和浏览器规则，转换自定义检查。两项既有活跃任务保留范围、授权、进度、证据和未决问题，Go 计划有唯一当前摘要，记者计划继续引用父 Spec 与唯一接口契约。历史 Draft、completed 和验证资料不重新授权或提升证据结论；执行前重建实际清单和哈希。

### AC-verification 真实验证与可读性

完成类型、源码/分发测试、构建一致性、迁移故障注入、包/Plugin、浏览器、纯文本与冷启动验证。两个交付项目按实际使用仅启用 Codex；Codex 实际新入口运行与社区 Adapter（含 Trae）的协议、分发回归分别报告。社区宿主无需为本次交付逐一打开，未实测的生命周期能力明确标记，不声称完整兼容。配置、静态测试、真实运行和人类接受不混淆。未参与讨论者能从两份真实任务和八篇 Wiki 理解当前结论、下一步、依据及限制，不能用字数或图数量代替阅读质量。
