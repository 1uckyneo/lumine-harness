# 界面实现约定

用户界面表达用户关心的对象、动作、状态和下一步。聊天备注、需求说明和生成内容进入界面前，应整理为正式产品文案，不直接展示开发变量、枚举、接口路径、异常栈或“演示／内部评审”等背景话术。

- 明确区分保存、发布、导出、刷新、重新生成和继续处理。
- 为适用的加载、空、未登录、无权限、失败、取消和可重试状态提供可理解反馈；技术原因保留在日志中。
- 核对键盘操作、焦点、可访问名称、长文本和窄屏；状态不只靠颜色表达。
- 复用项目已有视觉、组件和行为边界，不因共享呈现而合并不相同的状态或权限。
- 以真实页面及相关测试验证实现，设计预览或静态截图不能证明后端、持久化、权限或部署已通过。
