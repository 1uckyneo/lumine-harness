# Lumine 整体重构与工作流知识库交付

## 当前交付：2026-11-17 完整重构

### 工作顺序和责任

1. 固定原始内容与状态、当前读者问题和基线；读取适用规则并绑定原任务。
2. 并行修改互斥代码：知识理解／关系／上下文与缓存；正文协议与声明式解释；阅读器视觉／图示；主线程整合依赖、服务边界、发行与Skill。
3. 用真实中文长文校准字体、步骤、图示、搜索和来源；补充完整业务、技术和规范写作示范。
4. 串行集成后运行类型、构建、全测、生成、Skill与wrapper；隔离完整项目副本演练知识写入、人工保护、候选／冲突、恢复和无变化操作。
5. 记录30次预热、冷启动、字体发行与加载、离线、1024／1280／1440和200%缩放；通过真实浏览器观察，独立审阅知识质量与维护。
6. 核对自用知识、来源、当前证据及远端分歧，将同一main提交分别发布两源并核验。
7. 项目在指定工作分支采用已发布提交，再重组概念与能力、重写机械文章和历史混杂、提升规范入口；保留业务代码和恢复资料。项目Git提交／推送不在本计划授权内。

### 技术合同

- 复用稳定ID、主题、来源及关系，以公开context／impact入口准备任务与变化候选，保留人工和完整规范。没有Agent时不自行生成语义结论。
- 显式lumine-view围栏代替全局冒号猜测，字面正文保真；专题资源经登记和独立sandbox／CSP隔离。
- 中文Noto衬线标题＋Noto无衬线正文＋IBM Plex Mono代码；CSS变量和组件样式，React Aria交互，按需图示查看器；字体、许可证、SVG标识和favicon离线发行。
- Shiki小语言集在Node侧按内容缓存，正文独立可读；单操作复用文档和事务快照，历史回执不按每篇页面重复读取；外部编辑正确失效。
- 正文／图／导航／关系／来源作为相关变更，沿用显式更新、三方合并和恢复，不自动转换存储格式。
