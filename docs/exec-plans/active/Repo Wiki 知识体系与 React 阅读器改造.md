## 技术方案与取舍

### 1. 阅读器：替换视图，保留知识合同

在 `skills/lumine-harness/src/browser/` 下建立 React＋TypeScript 组件，沿用现有本地只读服务、`/api/catalog`、`/api/map`、`/api/document`、`/api/source`、`/api/reference` 的身份和来源合同。按项目首页、知识树、搜索、正文、来源面板、图查看器拆分组件；React 阅读层保留 Markdown 清理、Mermaid 安全阈值与离线绘图，服务端保留只读回环、CSP、路径和来源允许范围。调整 TSX 类型检查范围、React 依赖与构建入口，由 `scripts/build-reader.ts` 将依赖打进既有静态资产及清单，并核对许可；后续使用者按已确认的全局 Node 支持范围，在断网、无开发依赖下仍能阅读和绘图，不增加 SSR、云服务或运行时 CDN。

稳定文档／章节／图身份与 URL 承载分享位置；搜索、目录和面板状态优先放组件局部或 URL。当前无需引入 Zustand：先用小范围 React state 和明确的数据读取边界；如果实施时出现可复现的跨组件同步问题，再记录原因、最小状态范围和替代方案。阅读位置、筛选和目录展开按 `.lumine/root.json` 现有 `projectId` 隔离；关闭面板恢复焦点及正文位置，显式深链优先，根地址显示首页而非自动跳转文章。

在项目配置增加可选、经确认的展示名，随 `/api/config` 返回。源仓和目标父仓各配置自己的名称；旧项目没有名称时显示中性“项目知识库”，不从绝对路径或目录名猜测。暂时缺失源码的知识仍可读，但来源状态不能显示为已核实。中英文界面都覆盖加载、空、失败与恢复，不翻译正文。

### 2. 人类搜索与 Agent 查询分开

保留 CLI/Agent 默认最多六张文本卡片和现有总字符预算。浏览器新增有界的分页或游标查询，返回实际命中数、`hasMore`、稳定章节定位、可清除筛选及保留条件/否定的片段；排序和索引依据复用现有搜索实现。默认仅检索当前项目 Wiki；“全体文档”只含已登记且允许阅读的 Wiki、Spec、Plan，及项目配置明确登记范围内的适用验证资料。未登记的验证资料仍只通过明确引用访问，不递归索引本地私有材料。目录或索引在翻页期间变化时重新开始该查询，不重复或遗漏结果。

### 3. 原始 Markdown 与安全增量迁移

将源仓和父仓长篇 Wiki 的顶部声明收敛为稳定身份、标题、语言、类型、简短摘要；完整来源、章节、图和监控范围移到**同一 Markdown 文件尾部的受控结构化块**。先以源仓长文及父仓现有 JSON/YAML 两种 frontmatter 各一篇验证解析、可读性和差异保护，再确定块格式；不引入第二份知识事实或另建全文副本。解析器必须在返回正文前剥离尾部声明，使正文、目录、检索和图解均不暴露该块；校验器、模板、序列化器和更新引擎成对支持转换。旧格式保留有界读取以完成迁移，但日常写入只输出新格式。

转换前为正文与 `.lumine/wiki-state/` 的基线、人工审阅、候选、更新包和冲突建立清单与哈希；先恢复或处理待应用更新包，未解决的页面保持旧格式并跳过转换，不能让旧候选与新基线失配。隔离夹具验证文档/章节/图 ID、来源映射、关系、监控范围、稳定链接、人工修改与三方合并。仅格式移动不能使来源观察或语义审阅时间前移。任一文档无法证明无损时停止其转换，保留原文与恢复材料，报告未完成的 AC-002，不以批量覆盖凑完成。

### 4. 知识维护闭环与两项目内容

扩展现有扫描／任务记录，而非建立新的知识审批流程：对未精确引用文件按主题、来源范围和版本记录“需补解释／现有主题已覆盖／暂缓及理由”；范围或事实改变后使旧决定重新待核实。任务承诺知识同步时，记录本次变化影响、所采用的新增／修订／保留处置、对应知识版本及核实范围；Runtime 检查结构关联，Agent 核对结论语义。无增量和明确只读任务可以零更新。

两个项目各选真实问题审阅现有知识，先固定问题和判据，再核对源码、来源和适用限制。源仓优先检查根解析及 Wiki 增量机制的长文；父仓优先检查“三仓职责与系统运行边界”与“聊天流式输出与图片任务恢复”等跨仓、多来源页面。只有发现具体解释缺口才局部修订正文、关系或图解，并保留来源和人工差异；结构检查通过不等于语义通过。Agent 新上下文使用、至少一次来源演进后的增量使用、普通读者的理解分别留证；由未参与撰写者复评并保留原判据、首次答案与修正过程，不能从小样本推算长期节省比例。

### 5. 分发与目标父仓升级

源仓 TypeScript 是唯一 Runtime 源码；构建生成 `assets/**/*.mjs`，再同步 Plugin wrapper。中英文 README 对阅读路径、离线能力、安装方式与边界保持一致，Adapter 文档只在协议变化时更新。正式分发检查 React bundle、Mermaid、Markdown、许可和 CSP 资源无外链。

父仓先运行安装器的 `upgrade --plan` 产生逐文件提案并检查受管清单与项目资产边界，再依提案 `upgrade --apply`；不手工复制新阅读器覆盖项目内容。`.lumine/wiki-reader/` 是受管分发文件，`docs/repo-wiki/`、`.lumine/wiki-state/` 和活跃业务任务是项目资产。应用前后分别比较清单与哈希、目录/文档/图/来源身份及既有候选、冲突、审阅；问题可按提案恢复步骤处理，不以删除 `.lumine/local/` 代替恢复。
