# 实施、恢复与验证

<!-- LH-RUN-01 -->
读取 `AGENTS.md` 及其规范索引，按任务完整读取适用规范、模板与示例并执行编辑前门禁，再核对现有 Spec／Plan 和本轮授权；核实实际实现仓与已有修改。按当前目标自主选择 Wiki、源码或组合；明确位置的小修可以直接读代码，跨模块问题可借助目录与章节。不要以固定查询顺序或消息中的“检查”“执行”关键词决定动作。

<!-- LH-RUN-02 -->
先判断本轮结果：
- **实施／修复**：只改授权范围；按 Exec Plan 推进并维护当前进度、决定和下一步。
- **只验证／诊断**：执行适用检查或复现，报告结果、原因确定度和未覆盖范围；失败不能自动转为修复。证据写入也须符合请求；用户要求不改文件时仅输出报告。

<!-- LH-RUN-03 -->
进入或恢复实施时按 [阶段判断与交接](../lumine-plan/references/stage-handoff.md) 核实适用 Spec、设计、Exec Plan 及进入 Run 的确认；确认不足先报告具体缺口，不能凭早期整体授权补写 Plan 后自行开工。复杂功能缺少可执行方案时交给 `lumine-plan`，跨阶段仍须确认。符合项目直接处理条件的局部维护／修复可不创建长期 Spec／Plan，但仍需明确请求、目标、边界和验证；不得用此例外绕过产品变更的确认。阶段内自主实施；局部技术调整回写 Plan，产品行为或重要设计改变回到相应成果并重新确认受影响范围，保留无关有效确认。

开始或恢复实施前，读取与本轮目标对应的已有任务，核对目标、范围、模式、适用 Spec／Plan／AC 与授权；同一任务优先复用，没有适用记录时通过 Runtime 创建。局部修复可无长期 Spec／Plan，仍记录任务目标、范围和实际证据。普通讨论、知识查询和独立检查可直接处理，不为运行检查制造实施任务；明确只读时不创建或修改任务文件。

使用 `./.lumine/cli --help` 核对当前接口，任务字段及格式遵循当前 Runtime 合同与实际输出，不自造恢复命令或另建台账。先用 `task show <taskId>` 获取已有记录及 `recordHash`；需要新建或更新时用 `task record <task.json>` 保存，更新既有记录须附 `--expect <recordHash>`。复用与本轮目标、范围、模式及当前宿主会话一致的有效绑定；新用户实施轮、恢复现场或身份／范围／模式变化时重新核对，绑定缺失、过期或不匹配时实际执行 `task bind <taskId> --product <当前宿主> --session-id <当前会话> --mode <本轮模式>`。模式为 `plan`、`implement`、`verify` 或 `diagnose`，不能用诊断模式冒充实施。宿主与会话身份须来自可信当前上下文，无法可靠获得时报告绑定缺口，不伪造标识。绑定及记录都不替代授权。

<!-- LH-RUN-04 -->
验证属于 Run，可以在实施中或实施后进行，无需另设阶段确认；仍须遵守凭据、破坏性操作、部署及外部动作的授权边界。验证实际结果而非只有结构。为适用验收记录操作、结果、时间、代码／环境范围和证据；测试、真实运行、部署和用户接受分别表达。Runtime 检查不替代行为判断，不以“通过”自述冒充证据。详细记录放入 `docs/validation/`，Plan 保留摘要与链接。

涉及界面实现时，沿根授权规范入口读取适用约束，以真实页面操作和相关测试验证用户可见行为；设计预览或静态截图不能证明后端、持久化、权限与部署通过。

任务记录只保存本轮身份、适用引用、范围、当前摘要及版本化证据／知识处置，不复制 Plan 或 Validation 正文。实施中更新当前进度、下一步、阻塞和受影响依据，恢复时重新核对记录及来源版本；更新遵守上述并发哈希保护。收尾前实际执行 `task check <taskId> --json` 检查适用任务并处理本轮缺口；本来无需实施任务的讨论、查询与独立只读检查可仅报告相应范围，不制造通过记录。实际实施缺少任务或当前绑定时须明确报告缺口并在授权内补齐，不能据此豁免。结构通过不能代替真实验证，诊断发现失败也可完成诊断报告。

<!-- LH-RUN-05 -->
调查发现重要缺口、过期或矛盾时核实来源，并在授权范围内更新相关知识；稳定实现变化连同必要上下游说明写回，新增模块纳入目录。按需读取 `lumine-knowledge`，不重写无关页面，没有知识增量可以零更新。用户明确只读时不改文件。本任务要求的知识同步未完成不能整体报完成，无关欠账不阻塞。仅诊断完成可包含失败结果，不要求修复。遵守三态 `WORK_STATUS`：done／continue／blocked，阻塞原因与下一步另行说明。

<!-- LH-RUN-06 -->
并行写入必须分配互斥文件 owner、输入、验收和停止条件；集成串行收口，运行验证在相关实现集成后执行。保持仓库、业务只读和发布边界，不把实施授权扩展为提交、推送、部署或其他外部操作。
