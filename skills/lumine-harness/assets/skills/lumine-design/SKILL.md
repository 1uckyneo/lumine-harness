# 视觉与交互设计

<!-- LH-DESIGN-01 -->
读取项目 `AGENTS.md`、适用界面规则、Spec 和现有设计依据；进入、交接或恢复设计时按 [阶段判断与交接](../lumine-plan/references/stage-handoff.md) 核实当前成果及用户确认。产品方向先由 Spec 明确，用户确认进入设计后制作材料。产品规则归 `lumine-plan`，本 Skill 处理视觉与交互；技术架构设计归 Plan。审阅请求只输出判断和依据，不默认修改实现。

<!-- LH-DESIGN-02 -->
围绕尚未确定的视觉、交互或可行性问题选择最小有用材料，如 HTML 原型、流程图或设计说明。已有外部设计、参考图和获准方案可以复用；不要仅因进入新阶段重新生成附件，不强制同时写 DESIGN、component map 与两种 handoff。

<!-- LH-DESIGN-03 -->
明确材料覆盖的页面／状态、关联 Spec 与确认范围，阶段内自主迭代。完成后展示可审阅成果和未决事项，请用户确认设计并进入 Spec 补充；已有对同一成果的有效确认不重复询问。文件状态和 Agent 自评不能代替确认，不能凭早期整体授权直接进入技术规划或实施。

<!-- LH-DESIGN-04 -->
说明正常、加载、空、失败、无权限、取消与恢复中实际适用的状态；检查可访问性、窄屏、内容密度与用户文案。只写最终用户需要知道的对象、动作和下一步，不暴露开发备注。审阅产品目标与视觉／交互是否一致，确定性检查不能代替该判断。

<!-- LH-DESIGN-05 -->
用户确认设计后，由 `lumine-plan` 回到同一 Spec，补充设计确定的场景、行为、规则和验收，并链接材料；仅有呈现细节时更新引用和适用范围，不复制设计正文。展示补充后的 Spec，用户确认后才进入 Exec Plan；Plan 再确认后才进入 `lumine-run`，设计不直接交给实施。实现后的浏览器验证属于运行证据，不能用设计预览证明真实页面已交付。Repo Wiki 卡片采用文本／HTML，不通过本 Skill 生成图片。

<!-- LH-DESIGN-06 -->
按需查看已有产品、交互和界面知识，或直接核对实现；不要求先执行知识查询。在授权范围内将已落地、可复用的界面机制与限制写回知识，未实施设计继续留在 Spec 附件或 Plan。
