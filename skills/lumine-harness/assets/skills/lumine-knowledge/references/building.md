# 理解项目与全面建库

<!-- LH-BUILD-01 -->
先读真实入口、注册、配置、测试和有效决策，交叉识别主要能力、公共机制、模块依赖和运行边界。目录由项目用途与读者问题决定；库、CLI、单端应用、多仓系统应有不同结构。快速开始、API、前端、部署仅在实际需要时出现，不造空栏目。示例、未接入和历史内容明确分类。架构地图直接进入 Wiki；规范、示例、使用指南、已确认语言与长期决定按职责组织，不默认另建根架构文件或 domain/decisions 台账。采用与升级按[交付指导](delivery.md)补齐适用产物与资料去向。

<!-- LH-BUILD-02 -->
在 `.lumine/wiki-state/navigation.json` 建立读者路径，在 coverage.json 维护监控范围、主题问题、覆盖状态、文档引用和缺口。先从理解项目、开发与运行、查找与核实三个意图安排真实页面，再用覆盖问题核对缺失。每页只有一个主要位置，其他位置用有说明的关系引用。重要章节以稳定 ID 支持渐进阅读；章节没有独立审批或任务状态机。目录随模块新增、拆分、替代和移除而调整。

<!-- LH-BUILD-03 -->
默认深入覆盖所有主要模块，允许用户明确缩小或延后。先形成实际问题：入口到数据与外部依赖如何协作；正常、失败、取消和恢复怎样处理；约束和不变量是什么；修改会影响谁、怎样验证。以这些问题衡量覆盖，不能用页数、字数、图数或逐文件清单代替质量。

<!-- LH-BUILD-04 -->
Agent／模型读取来源并撰写连贯解释、技术取舍和 Mermaid，核实跨模块链路。依据记录解释设计理由，只有代码时标为推断；源码事实、运行观察与部署状态分开。共享机制只完整写一处，模块页说明自己的差异。章节摘要与卡片复用正文，不创建另一套知识正文。

<!-- LH-BUILD-05 -->
大型项目分批推进，可给并行 worker 分配互斥页面、明确来源与问题，串行整合依赖和目录。保留已完成主题、剩余问题、冲突和恢复位置。工具安装、语义撰写、质量验收分别报告；部分完成不能冒充全面建库完成。没有活动 Agent 时，Runtime 只能保存待处理内容。

<!-- LH-BUILD-06 -->
使用未参与撰写的 reviewer 对照源码回答机制、修改影响、异常与验证问题，跨模块链路另验。结构检查、来源未变和作者自检均不能冒充独立语义审阅。记录审阅的正文版本、来源快照、范围、发现和限制。再让冷启动 Agent 自主选择 Wiki 或源码解决真实问题，验证知识可找到、可理解、可定位来源。

## 验收阅读主线

新手从首页直接进入功能或核心能力。用真实任务验证一个跨模块场景，检查能否解释角色交接、状态变化和例外。模块按需要提供短摘要、使用入口、重要规则、限制和来源。实现、计划、历史和验证分别明确。以独立读者、冷启动 Agent 和后续增量三组题验收。

首次编排先为候选页面写出一个主要读者问题、受众和职责，放入同一页 `reading` 元数据；来源范围和主题包含仍复用 coverage，调用与交接关系用 relations。检查这组问题是否能建立项目整体模型，再确定目录。菜单、源码路径、用户列举的个别缺口都是调查线索，不直接成为全库骨架。写作采用[完整范式与复读方法](写作与编排.md)，无需新增知识规划文件或重复事实库。
