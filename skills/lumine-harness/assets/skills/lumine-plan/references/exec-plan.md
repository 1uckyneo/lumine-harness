# 技术执行计划

<!-- LH-EXEC-01 -->
Exec Plan 将已明确目标转为可实施、可恢复、可验证的工作。使用稳定 `id`、`type: exec-plan`、自身 `locale` 和真实状态，通过 `specId` 或 `specIds` 引用产品方案。验收引用包含适用 AC 编号与基线；不复制产品正文。多个 Plan 可以引用同一个 Spec 的不同部分。

<!-- LH-EXEC-02 -->
开头维护唯一当前概览：已完成结果、剩余工作、下一步与阻塞。随后记录关键技术选择、理由、受影响仓库／模块、依赖、按结果组织的里程碑及验证方式。记录足以让另一个 Agent 接手的入口和上下文，不重复源码说明或堆叠更新流水账。

<!-- LH-EXEC-03 -->
复杂技术方案可以使用 Mermaid 表达目标结构、数据流、状态或时序，明确尚未实施。现状从 Wiki／源码引用；计划实施后才将稳定结论整理为 Wiki。局部技术调整维护 Plan；产品行为变化评估 Spec、验收基线和批准范围。

<!-- LH-EXEC-04 -->
写清本次可写与只读仓库、并行文件 owner、授权边界及必要恢复方法。按 [阶段判断与交接](stage-handoff.md) 检查已确认的 Spec 和必要设计依据，再进入技术规划。展示可执行的 Plan，用户明确确认该计划并进入 Run 后才实施；早期整体授权、Plan 生成或状态字段均不能替代此确认。已经确认且仍适用的同一 Plan 不重复审批。实施确认不产生提交、推送或发布授权；只要求技术讨论时，不执行实现。

<!-- LH-EXEC-05 -->
验证摘要链接到 `docs/validation/`，区分自动测试、实际运行、部署与人工接受。任务记录由 `.lumine/` Runtime 管理，字段和命令以 CLI 帮助为准；文档展示读者需要的当前结果和证据，不重复维护机器状态。收尾报告本次结果、未验证范围和下一步；整体未完成时不归档成完成。

计划完成后，可用 `task doc-archive <文档ID> --expect <当前SHA256>` 移入 completed；重新开启同一任务时用 `task doc-restore` 恢复。先用 `task doc-resolve` 读取当前版本；归档保留文档身份和证据，默认目录不加载历史，显式引用仍可追溯。
