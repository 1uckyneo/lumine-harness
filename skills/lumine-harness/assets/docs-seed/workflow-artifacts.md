# 工作资料如何分工

Lumine 让目标、技术方案、已有知识和实际证据各有一处可信记录。用户提出自然语言目标，Agent 判断当前阶段、所需能力与下一步；用户确认阶段交接，不需要手动选择 Skill。

| 资料 | 回答的问题 | 维护方式 |
| --- | --- | --- |
| Product Spec | 为谁解决什么问题，行为与范围是什么，怎样验收？ | 产品方案原位迭代；先概览，再场景、规则和稳定 AC。 |
| Exec Plan | 这次怎样实现，现在到哪里，下一步是什么？ | 引用适用 Spec／AC，维护当前技术方案、进度和证据摘要。 |
| Repo Wiki | 已有机制、确认的领域语言与长期决定、工程规范和使用方法是什么？ | 现状、规范、示例、指南分清效力和实现状态；每项一份正文，引用来源与有效决定。 |
| Validation | 实际做了什么，结果是什么，能证明到哪一步？ | 保留日期、操作、代码／环境适用范围与原始证据，不改写历史结论。 |

产品工作按 Spec →（必要设计 → 补充 Spec）→ Exec Plan → Run 推进，各阶段交接需人的明确确认；无需设计时省略设计及回写分支。Agent 先核对目标、材料、仓库事实和适用 Skill，再给出下一步判断，阶段内自主。只讨论 Spec 不产生技术 Plan；Run 中或之后的验证不另设确认。局部明确修复、规则维护和仅验证按自身范围处理，不强制补全产品流程。详细判断、确认依据与恢复方式见[阶段交接](../.agents/skills/lumine-plan/references/stage-handoff.md)，本页只维护资料职责。

## 日常能力

- `lumine-plan`：产品和技术规划及语义审阅。
- `lumine-run`：实施、恢复、验证和诊断；只验证不自动修复。
- `lumine-knowledge`：定位、检索和维护知识。
- `lumine-design`：具体视觉和交互选择。

`./.lumine/cli` 提供确定性检查，不能替代上述语义判断。诊断收口可以报告失败，不代表需要自动修复。

## 关联、语言与历史

文档、验收、章节和图使用稳定身份，与可读文件名分开。新正文及主题文件名默认跟随项目 locale，保留 README、模板名及必要技术词；已有资料不批量改名，名称遵守 Windows 保留名、非法字符、末尾点／空格与大小写／Unicode 重名限制。Spec 的一项变化只复核引用该项的 Plan，内容指纹不代表批准。历史证据继续适用于原基线。

项目语言控制新内容默认值，已有文档保持自己的语言。先呈现当前结论，再给技术细节与历史；省略不适用章节，完整日志通过链接访问。设计材料按需要选择，不复制固定附件套件。

## 知识与实现

Plan 中的拟议方案不能提前变成 Wiki 实现事实。确认的领域语言和长期决定可在相关 Wiki 主题保存，明确确认依据、上下文和未实施边界；完整术语与必要 ADR 不另建 domain/decisions 台账。AGENTS 可直接授权 Wiki 规范附件；规范、讲解示例与实现事实效力不同，普通知识同步不得放宽规则。架构地图进入 Wiki，不默认另建根 ARCHITECTURE。源码、实测与部署范围分别说明。

知识由 Agent 理解来源后维护：目录按项目实际能力组织，首次默认覆盖主要模块；任务中自主选择 Wiki、源码或组合，不强制查询。核实缺口、过期或矛盾后，把授权范围内的可复用结论写回受影响主题；明确只读时只报告。工具负责搜索、变化线索和保护性保存，不能代替语义理解。

收尾使用 done、continue、blocked 三种控制状态，具体阻塞原因与下一步另行说明。状态不增加授权，讨论、诊断、实施、运行验证和部署按当前请求分别判断。

## 追问与长期沉淀

规划中的 grill 按关键歧义、规则冲突和重要取舍自动按需使用，不对明确任务机械访谈。每轮回答在继续提问前写回本阶段同一 Spec／Plan：产品方向、术语、范围与 AC 归 Spec，技术取舍、依赖与验证归 Plan。产品阶段出现的技术约束先记 Spec，不提前生成 Plan；回答、接受推荐和内容指纹不产生阶段批准。未答和部分回答保持待决，不保存逐字聊天副本。

跨任务稳定的完整领域语言、同词多上下文和满足长期记录门槛的决定归相关 Wiki 主题；Spec／Plan 链接它们，保留原始决定依据与替代关系。不会因每轮回答都已回写而把每个答案强制升级成 ADR。

## 参考、历史与采用交付

原始需求和接口材料留在参考位置，历史留只读归档，个人配置和私密原件留已忽略本地位置；操作脚本与 Skill 留执行目录，Wiki 解释并引用。旧层退休前盘点角色和去向、保全原件、归位独有内容、修复活跃引用；无法安全退休则保留报告，不长期双写业务记忆。

首次采用交付 Wiki 内项目化 Lumine 协作、操作与服务指南及主要模块知识；实际服务扩展按项目需要复用或生成，不继承别处的全局安装授权。安装、内容完成、实际使用分开验收。Validation 记清单和证据，coverage 记主题／缺口，task knowledge 记版本化处置；沿用现有恢复位置，不新增状态机或改变 migration complete。升级仅补本轮受影响指引与缺口。
