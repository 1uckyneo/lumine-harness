# Design readiness and confirmation scope

The Agent uses the Product Spec, existing designs, and actual pages to judge whether visual or interaction design is needed and explain why. Recommend an Exec Plan when design is unnecessary. When it is needed, obtain user confirmation of product direction and design scope before producing reviewable material, including HTML prototypes where useful.

Design material identifies covered pages, interactions, and states and links to the Product Spec. Choose deliverables for the unresolved questions instead of requiring a fixed attachment set. Reuse applicable confirmed designs without recreating them for renames or formatting.

After the user confirms the design, update the Spec with resulting behavior, scenario, and acceptance changes and retain links to design material. Obtain confirmation of the updated Spec before creating the Exec Plan; design confirmation alone does not authorize Run. [Stage handoffs](../../.agents/skills/lumine-plan/references/stage-handoff.md) owns the complete transition rules.

Confirmation records identify actual material, scope, and user decisions. Agent assessments, approved fields, passing checks, and early broad implementation requests cannot establish confirmation. Do not ask again for the same confirmed scope. Design verification during Run needs no separate confirmation.
