# Target topology and scope

Single repositories, frontend-only, backend-only, full-stack, library/CLI, and multi-repository projects share one core contract. Topology selects relevant modules, not mandatory document counts. A package.json alone does not justify frontend design or browser work.

Inspect actual Git boundaries, application entry points, build manifests, route/data entry points, existing AGENTS and shared Skills, and host configuration. A host configuration file identifies a possible integration surface, not successful loading or execution.

For multiple repositories, register stable repository IDs, relative locations, and write boundaries before resolving knowledge sources. A common parent need not have Git. Organize a single repository by real modules without inventing child repositories.

The proposal identifies the adoption root, implementation surfaces, existing rules, technical signals, adapters, language, and inapplicable capabilities. Preserve read-only repositories, independent Git boundaries, and project-owned business constraints.
