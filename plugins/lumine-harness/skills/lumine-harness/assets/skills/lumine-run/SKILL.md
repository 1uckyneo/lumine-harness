# 实施、恢复与验证

<!-- LH-RUN-01 -->
读取 `AGENTS.md`、适用业务规则、现有 Spec／Plan 和本轮授权；核实实际实现仓与已有修改。新目标、范围变化和恢复时按需用 `lumine-knowledge` 检索，并核对相关源码。不要仅按消息中的“检查”或“执行”关键词决定动作。

<!-- LH-RUN-02 -->
先判断本轮结果：
- **实施／修复**：只改授权范围；按 Exec Plan 推进并维护当前进度、决定和下一步。
- **只验证／诊断**：执行适用检查或复现，报告结果、原因确定度和未覆盖范围；失败不能自动转为修复。证据写入也须符合请求；用户要求不改文件时仅输出报告。

<!-- LH-RUN-03 -->
复杂功能缺少可执行方案时用 `lumine-plan` 补齐必要信息；已授权工作自动衔接，不增加阶段审批。符合项目直接处理条件的小修复可不创建长期 Spec／Plan，但仍需目标、边界和验证。技术调整回写 Plan；产品行为合同变化由 `lumine-plan` 评估受影响验收与授权。新视觉取舍由 `lumine-design` 处理，不重做已批准设计。

<!-- LH-RUN-04 -->
验证实际结果而非只有结构。为适用验收记录操作、结果、时间、代码／环境范围和证据；测试、真实运行、部署和用户接受分别表达。Runtime 检查不替代行为判断，不以“通过”自述冒充证据。详细记录放入 `docs/validation/`，Plan 保留摘要与链接。

<!-- LH-RUN-05 -->
只同步受影响知识；更新时用 `lumine-knowledge`。本次明确包含的知识同步未完成不能整体报完成，无关页面过期不阻塞任务。诊断的 done 表示检查与报告已完成，可以包含失败结果，不要求修复被检查对象。遵守项目 WORK_STATUS 约定。

<!-- LH-RUN-06 -->
并行写入必须分配互斥文件 owner、输入、验收和停止条件；集成串行收口，运行验证在相关实现集成后执行。保持仓库、业务只读和发布边界，不把实施授权扩展为提交、推送、部署或其他外部操作。
