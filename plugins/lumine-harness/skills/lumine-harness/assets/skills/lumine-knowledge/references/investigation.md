# 调查与检索

<!-- LH-SEARCH-01 -->
从当前目标而非工具列表出发。知道实现位置时可直接读源码；需要全貌时查看 `wiki map`，需要具体机制时用 `wiki query`，按 `wiki show <文档ID>#<片段ID>` 展开章节或图；用 `wiki related` 查看有说明的关联。也可以直接读 Markdown。用户不需要逐条执行命令，Agent 不必全部调用。

<!-- LH-SEARCH-02 -->
阅读命中片段的限定条件、范围、来源、最近核对时间和语义审阅信息。中文、英文和代码符号可能需要别名或当前模型重述查询；工具不提供任意跨语言语义翻译。无可靠结果应报告不足，不把通用问句词造成的命中当答案。检索索引只说明已保存文本，不能证明源码现在没有变化。

<!-- LH-SEARCH-03 -->
核实重要结论时回到登记源码、有效规则和适用运行证据。缺口、过期或矛盾可产生知识增量：在授权范围内补充解释、修正来源或别名；只读要求则报告建议。只维护受影响内容，保留未知与争议，不为每次查询写日志。状态扫描只能提供变化线索，语义判断和撰写由当前 Agent 完成。

<!-- LH-SEARCH-04 -->
结论附稳定引用和必要源码位置，区分开发事实、推断、运行观察和部署限制。不要把 Wiki 当另一套授权规则，也不要将未实施方案写成当前实现。目录、卡片和工具只是调查辅助，真正效果以新会话的任务正确性与重复调查成本检验。
