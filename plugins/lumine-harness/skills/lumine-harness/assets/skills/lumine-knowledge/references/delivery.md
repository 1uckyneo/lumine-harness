# 采用交付与验收

首次采用和升级中的知识交付使用本指导，不把安装工具完成当成项目内容完成。沿用现有 Validation、coverage、task knowledge 与 Plan 恢复；不另建状态机或修改 migration complete 的安装含义。

## 首次采用默认交付

- 项目化 Lumine 协作指南：怎样提出目标、理解四个能力、审阅具体成果、确认阶段、继续会话和判断证据。链接已安装阶段规则，不复制另一套授权状态机。
- 操作与服务指南：本项目可用的自然语言操作、实际入口和前置条件；区分业务服务与阅读器，给出启动／重启／停止／状态及失败下一步。服务按[服务扩展](services.md)复用或生成；不适用的服务明确省略。
- 资料角色与导航：AGENTS 的最小硬规则直达规范附件与 Wiki，架构地图归 Wiki；规范、示例、实现、确认的领域语言与长期决定明确效力和实现边界。业务目标与技术方案仍分别归 Spec／Plan。
- 资料去向审计：原规则、架构、示例、业务记忆、参考、历史、个人及私有资料各有去向。退休旧层前保护原件、迁移独有内容、修复活动引用，不能安全退休则保留并说明；不为匹配目录删除资料。
- 主要能力覆盖：围绕机制、异常、影响和验证的问题建库，不用页数衡量完成。完整术语、同词多上下文、关键不变量与必要 ADR 进入适用主题，关联有效决定来源，不另建 domain/decisions 目录。

指南是项目事实的说明，由 Agent 按当前规则、已安装能力和核实入口撰写，加入知识地图并从首页可达。新文档及文件名默认跟随项目 locale，稳定身份独立；不批量改名历史。仅写已具备能力和已确认语言，不提前宣称计划已落地。

## 分层验收

1. **安装**：分发、根解析、配置、恢复记录与选定宿主安装证据；受 migration 合同约束。
2. **内容**：以上适用产物可导航、角色和效力无冲突、主要问题有答案或明确缺口。独立 reviewer 核对正文版本、来源和跨模块关系；作者检查不能冒充独立审阅。
3. **实际使用**：冷启动 Agent 自主找出规则、解释一个真实机制并定位来源；在可用环境验证人类阅读器导航、搜索和图。项目服务、真实 Skill 读取及 Hook 另验。没有能力或环境时明确未验证，不补造通过。

用 `docs/templates/adoption-validation.md` 记录本轮清单、处置、证据与未覆盖范围；coverage 维护问题、文档引用与 planned/partial/covered/deferred。任务 knowledge 记录版本化来源、核实范围、created/revised/retained/deferred、理由和内容哈希。`covered` 和 `wiki check` 不证明语义、运行或用户接受；Agent 必须核对实际内容。

用户缩小或延后时，保存适用确认、剩余问题与恢复位置，明确本轮交付边界。升级只处理本轮受影响的指南、规则、模块、术语及缺口，保留有效人工内容和并行任务；不重新全库生成或重新定义其他业务需求。
