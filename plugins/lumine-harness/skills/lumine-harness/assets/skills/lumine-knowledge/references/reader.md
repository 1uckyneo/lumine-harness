# 启动、重启与停止 Wiki 阅读器

用户要求“打开／查看知识库”“启动／重启／停止 Wiki 阅读器”时使用本参考。只需阅读 Markdown、查询知识或维护正文时，无需启动服务；打开阅读器也不触发建库或全库更新。

## 运行前提与项目归属

阅读器和依赖随 Lumine 安装，运行需要 Node.js 22.x（22.18.0 及以上）或 Node.js 24.x LTS（24.11.0 及以上）及现代浏览器，推荐 Node.js 24 LTS；无需安装 npm 依赖、连接模型或启动业务服务。使用已确认的 Harness 根，其 `.lumine/cli` 会定位正确 Runtime；不要从业务子仓的最近 Git 根推定项目归属。普通采用项目也可用 `node .lumine/wiki.mjs serve` 绕过 Bash 包装器；源仓自用应使用自己的 `.lumine/cli`。

先查看当前会话的进程句柄、启动日志和必要的监听信息。确认服务属于当前 Harness 根后，再决定复用或停止：

- 优先使用本会话保存的进程句柄与明确的启动根。
- 对其他会话留下的进程，核实 PID 的启动命令、`--root` 或工作目录及监听地址；发送信号前重新检查，防止 PID 已被复用。
- 端口、HTTP 200 和 `/api/config` 中的仓库 ID 只能辅助核对，不能单独证明归属。当前 Runtime 不提供阅读器专用 PID 注册表或 `status/stop/restart` 命令。
- 归属不明时不要终止进程。打开请求可使用其他空闲端口；停止／重启请求应说明无法安全定位，并索取已有终端或启动信息。

## 打开或启动

已有属于当前项目且可访问的服务时复用其地址。需要新进程时，在 Harness 根执行：

```bash
./.lumine/cli wiki serve --root "$PWD"
```

默认监听 `127.0.0.1:4318`。端口被其他项目占用时，保留其进程并选用空闲端口，例如 `--port 4319`；也可使用 `--port 0` 让系统分配，始终采用命令实际返回的 URL。路径包含空格时保持引用。

使用宿主可持续保留的终端或进程会话运行前台服务，保存句柄、项目根与返回地址以便后续操作。宿主不支持跨回合保活时，说明限制并给出可由用户持续运行的命令，不把临时进程承诺为常驻服务。不默认添加系统自启或后台守护。

确认进程存活、返回地址可访问，且 `/api/config` 或目录对应预期项目，然后用可用浏览器工具打开该地址；不能自动打开时返回可点击链接。仅完成 HTTP 探测时只报告服务可达，不声称图解或交互已验证。服务只监听回环地址，不扩大监听范围。

## 停止

对本会话启动的服务，优先通过原终端发送 `Ctrl+C`；也可向已重新确认归属的 PID 发送 `SIGTERM`，等待退出。无相关进程时报告“已停止”。不能通过端口批量杀进程、`pkill node` 或默认 `kill -9` 处理。

确认目标进程已退出。若端口仍有响应，重新检查占用者，不连带终止另一个进程。关闭浏览器标签页不等于停止服务；停止服务也不删除正文、索引、维护状态或日志。

## 重启

记录当前根和实际端口，按上述方法停止目标服务，确认退出后以相同配置重新启动。指定端口重启时若发生冲突，保留占用者并报告或选择新端口；使用 `--port 0` 时新地址可能改变。重新核对服务并给出最终 URL。

仅修改正文通常刷新页面即可，不需要重启。Runtime 或启动时读取的配置更新后需要重启；阅读器静态文件更新通常刷新即可，安装布局改变时重启。不要把浏览器刷新描述成服务重启。

## 结果与故障反馈

简短说明复用／新启动／已重启／已停止、项目、实际地址及必要限制。Node 缺失、资源缺失、端口占用或权限不足时给出具体原因和下一步。资源缺失应通过 Lumine 维护入口修复安装，不临时从 CDN 补资源；停止／重启失败时保留已有资料并如实说明，不能虚报成功。
