# 理解项目与全面建库

<!-- LH-BUILD-01 -->
先读真实入口、注册、配置、测试和有效决策，交叉识别主要能力、公共机制、模块依赖和运行边界。目录由项目用途与读者问题决定；库、CLI、单端应用、多仓系统应有不同结构。快速开始、API、前端、部署仅在实际需要时出现，不造空栏目。示例、未接入和历史内容明确分类。

<!-- LH-BUILD-02 -->
在 `.lumine/wiki-state/coverage.json` 维护主题层级、同级顺序、问题、来源范围、文档引用及缺口，作为导航唯一来源。每页只有一个主要位置，其他位置用有说明的关系引用。重要章节以稳定 ID 支持渐进阅读；章节没有独立审批或任务状态机。目录随模块新增、拆分、替代和移除而调整。

<!-- LH-BUILD-03 -->
默认深入覆盖所有主要模块，允许用户明确缩小或延后。先形成实际问题：入口到数据与外部依赖如何协作；正常、失败、取消和恢复怎样处理；约束和不变量是什么；修改会影响谁、怎样验证。以这些问题衡量覆盖，不能用页数、字数、图数或逐文件清单代替质量。

<!-- LH-BUILD-04 -->
Agent／模型读取来源并撰写连贯解释、技术取舍和 Mermaid，核实跨模块链路。依据记录解释设计理由，只有代码时标为推断；源码事实、运行观察与部署状态分开。共享机制只完整写一处，模块页说明自己的差异。章节摘要与卡片复用正文，不创建另一套知识正文。

<!-- LH-BUILD-05 -->
大型项目分批推进，可给并行 worker 分配互斥页面、明确来源与问题，串行整合依赖和目录。保留已完成主题、剩余问题、冲突和恢复位置。工具安装、语义撰写、质量验收分别报告；部分完成不能冒充全面建库完成。没有活动 Agent 时，Runtime 只能保存待处理内容。

<!-- LH-BUILD-06 -->
使用未参与撰写的 reviewer 对照源码回答机制、修改影响、异常与验证问题，跨模块链路另验。结构检查、来源未变和作者自检均不能冒充独立语义审阅。记录审阅的正文版本、来源快照、范围、发现和限制。再让冷启动 Agent 自主选择 Wiki 或源码解决真实问题，验证知识可找到、可理解、可定位来源。
