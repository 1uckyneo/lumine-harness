# 项目知识

<!-- LH-KNOWLEDGE-01 -->
先读 `AGENTS.md` 的约束与工程地图，使用已确认 Harness 根和 `.lumine/project.json` 配置。Wiki 默认在 `docs/repo-wiki/`，以配置为准；不能把最近 Git 根当多仓 Harness 根。检索不会替代必须读取的项目规则。

<!-- LH-KNOWLEDGE-02 -->
只查询时先用 `./.lumine/cli wiki query`／`show`，检查范围、来源和时效；无答案、过期或矛盾时回到源码。按需展开相关正文，默认最多六张卡片并控制总上下文；中文、英文和代码标识符可通过同义词或查询重述交叉查找。不要为一次定位强制生成全仓知识。

<!-- LH-KNOWLEDGE-03 -->
维护时读取 [知识维护](references/maintenance.md)。使用 `wiki scan` 识别变化，`wiki update` 准备工作包并应用语义结果；以命令帮助的参数合同为准。CLI 提供确定性机制，当前 Agent 负责理解与核实；没有活动 Agent 时不能宣称后台语义更新完成。

<!-- LH-KNOWLEDGE-04 -->
正文、摘要、Mermaid 文本和来源是人／Agent 共用的一份内容。卡片由 HTML DOM 呈现，图由浏览器即时渲染。知识扫描、生成、更新、查询和审阅只接收文本，不调用图片生成、截图识别或视觉模型，不生成卡片图片或缩略图文件，不把渲染后的 SVG 送入模型。文本复制／导出使用 Markdown 或 Mermaid。浏览器专项 UI 验证与知识流水线分开。

<!-- LH-KNOWLEDGE-05 -->
语义审阅须核对实际来源和重要关系。Wiki 描述已知实现，Spec 描述目标，Plan 描述此次技术变化；不能将未实施方案写成现状。工程约定只解释并引用权威规则；设计理由缺乏记录时标为推断，源码不能证明部署与运行结果。

<!-- LH-KNOWLEDGE-06 -->
按问题组织“回答→机制与图解→取舍和限制→来源”。为图保留稳定身份、读图说明和依据；复杂主题拆页，禁止用文件清单或密集网络冒充解释。正文中的 Mermaid 是唯一图源，修改后同步摘要、关系和时效。保护人工修改、有效候选和冲突；缓存可重建不等于重新调用模型生成。
