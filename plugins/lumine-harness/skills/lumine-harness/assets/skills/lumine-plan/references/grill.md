# 内置 grill 与回写

<!-- LH-GRILL-01 -->
用户明确要求 grill／压力测试，或存在会影响产品方向、验收、实体边界或重要实施选择的歧义、冲突和取舍时，读取本 Skill 的 [grilling 完整模块](../vendor/grilling/INSTRUCTIONS.md)。涉及术语、实体关系、上下文边界或需要长期解释的决定时，读取 [domain-modeling 完整模块](../vendor/domain-modeling/INSTRUCTIONS.md) 及其适用格式。只需理解已有术语时，直接读对应资料；不因任务进入规划阶段而自动进行完整访谈。

这些是分发包内置的完整适配模块，不调用全局同名 Skill，不要求额外安装，也不在使用时获取上游代码。[来源、许可证与适配记录](../vendor/SOURCE.md) 和 `vendor/manifest.json` 用于维护与完整性检查，不是每次任务的必读材料。

<!-- LH-GRILL-02 -->
按完整设计树组织澄清，每轮列出当前全部已满足前置条件的问题，逐项编号并给出推荐；依赖尚未解决问题或事实调查的问题留到后续。事实由 Agent 调查，可委派；事实未返回只阻塞依赖分支。保留用户未答、部分回答及明确不同意的内容，不把沉默当同意，不为尽早结束缩减范围。用户另有提问节奏偏好时遵守。

每轮收到回答后，先回写已经明确的方向与仍有影响的未决问题，再继续提问。恢复时读取现有成果和确认依据，重建未决问题及依赖，不重复询问已解决内容；不新增访谈数据库。

<!-- LH-GRILL-03 -->
| 已明确内容 | 写回位置 |
|---|---|
| 产品目标、行为、范围、验收及普通产品选择 | 当前 Product Spec |
| 本次实施方案、技术取舍、依赖与恢复方式 | 当前 Exec Plan |
| 已确定的共享术语、Avoid 同义词、实体边界及多上下文关系 | Wiki 领域语言专题／稳定章节，或已有等价权威资料 |
| 同时满足难以逆转、缺少背景难以理解、确有备选方案的重要长期决定 | Wiki 决策专题／稳定章节，或已有等价权威记录 |
| 已核实实现和实际验证结果 | 对应 Wiki 实现专题和 Validation；不把产品决定写成已实现 |

普通回答无须满足长期决策门槛才能回写。产品阶段中的技术约束先记录在 Spec，不提前生成 Exec Plan。已有等价资料优先复用，按内容创建 Wiki 专题或章节，不创建空资料，也不默认新建 `docs/domain/`、`docs/decisions/`、`docs/adr/` 或根词表。Spec／Plan 链接术语与长期决定，长期记录保留形成依据、身份与替代关系；具体格式在内置 domain-modeling 中。

<!-- LH-GRILL-04 -->
遵守 Wiki 的来源、文档类型和 `proposed/current/historical` 状态契约。已确认的领域语言和决定可以是当前有效记录；这不表示相应功能已经实现。改变产品规则或验收含义的领域／决策变化，回写受影响的 Spec／AC 正文并复核对应确认；仅修改被链接 Wiki 不会更新验收基线。

当全部相关分支已解决、没有待返回事实前置项时，展示共同理解并请求对应阶段确认。可与已有 [阶段交接](stage-handoff.md) 的具体成果确认合并，不增加额外确认门槛。问题回答、推荐接受及文档写回都不能代替跨阶段授权；有效的同一范围确认不重复询问。明确只读时仅展示拟回写内容。
