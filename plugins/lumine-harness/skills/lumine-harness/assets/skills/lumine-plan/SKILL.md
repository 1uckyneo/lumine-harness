# 需求与方案规划

<!-- LH-PLAN-01 -->
按用户本轮希望得到的结果工作。先读项目 `AGENTS.md`、适用规则与现有任务。自主选择 Wiki、源码或组合来理解现状与影响，不要求每个任务查询。重要知识缺失、过期或矛盾时核实源码；在授权范围内沉淀可复用结论，需要深入方法时读取 `lumine-knowledge`。只读请求保持只读。

<!-- LH-PLAN-02 -->
- 产品问题、场景、规则与验收：读 [产品方案](references/product-spec.md)，原位维护 Spec。
- 技术取舍、实施顺序与恢复：读 [执行计划](references/exec-plan.md)，引用 Spec 的适用验收项。
- 只讨论或修改 Spec 时不强制创建 Exec Plan。只审阅方案时给出问题、依据和最小修正，不开始实现。
- 新的视觉或交互选择需要具体材料时使用 `lumine-design`；产品规则仍由 Spec 维护。

<!-- LH-PLAN-03 -->
完整功能默认使用 Spec＋Plan；没有新产品决策、不改变既定行为合同、不需要独立跨任务协调的局部修复可以直接交给 `lumine-run`。不能按文件数判断简单与否。

<!-- LH-PLAN-04 -->
复用已有授权，阶段切换不增加确认。发现影响目标、范围或重要取舍的未决问题时提出具体选择；不要把写入 `approved`、生成文档或内容指纹当作用户授权。已获实施授权且方案明确时连续交给 `lumine-run`；本轮只要求规划时在规划结果收口。

<!-- LH-PLAN-05 -->
评审产品和技术方案是否一致、是否能验收、是否遗漏边界。Runtime 检查结构和引用，不能代替语义评审。正文先写结论与当前决定，省略不适用章节，不复制日志；遵守项目语言，允许中文文件名，身份与标题分离。
