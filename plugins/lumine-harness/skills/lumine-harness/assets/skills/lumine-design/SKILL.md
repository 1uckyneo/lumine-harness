# 视觉与交互设计

<!-- LH-DESIGN-01 -->
读取项目 `AGENTS.md`、适用界面规则、Spec 和现有设计依据。先区分产品行为问题与具体呈现选择：前者交给 `lumine-plan`，后者在本 Skill 内处理。审阅请求只输出判断和依据，不默认修改实现。

<!-- LH-DESIGN-02 -->
围绕尚未确定的视觉、交互或可行性问题选择最小有用材料，如 HTML 原型、流程图或设计说明。已有外部设计、参考图和获准方案可以复用；不要仅因进入新阶段重新生成附件，不强制同时写 DESIGN、component map 与两种 handoff。

<!-- LH-DESIGN-03 -->
明确材料覆盖的页面／状态、关联 Spec 与批准范围。新的实质取舍需要具体可审阅的选择；已有明确授权继续有效。文件状态和 Agent 自评不能代替用户批准。不得把未批准的新方向当作已批准实现依据。

<!-- LH-DESIGN-04 -->
说明正常、加载、空、失败、无权限、取消与恢复中实际适用的状态；检查可访问性、窄屏、内容密度与用户文案。只写最终用户需要知道的对象、动作和下一步，不暴露开发备注。审阅产品目标与视觉／交互是否一致，确定性检查不能代替该判断。

<!-- LH-DESIGN-05 -->
以链接将设计材料附于 Spec，实施映射和偏差放入 Exec Plan；一处维护完整说明。获准实现使用 `lumine-run`，实现后的浏览器验证属于运行证据，不能用设计预览证明真实页面已交付。Repo Wiki 卡片采用文本／HTML，不通过本 Skill 生成图片。

<!-- LH-DESIGN-06 -->
按需查看已有产品、交互和界面知识，或直接核对实现；不要求先执行知识查询。在授权范围内将已落地、可复用的界面机制与限制写回知识，未实施设计继续留在 Spec 附件或 Plan。
