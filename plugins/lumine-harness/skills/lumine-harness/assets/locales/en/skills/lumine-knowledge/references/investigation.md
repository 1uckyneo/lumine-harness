# Investigation and retrieval

<!-- LH-SEARCH-01 -->
Start from the goal, not a tool checklist. Inspect source directly when the implementation location is known. Use `wiki map` for orientation, `wiki query` for a mechanism, `wiki show <document-id>#<fragment-id>` to expand a section or diagram, and `wiki related` for explained relationships. Direct Markdown reading is also valid. Users need not invoke each command, and Agents need not call them all.

<!-- LH-SEARCH-02 -->
Preserve qualifications in excerpts and inspect scope, sources, last source check, and semantic review. Chinese, English, and code queries may require aliases or model-led reformulation; the tool does not promise arbitrary cross-language semantic translation. Report insufficient results instead of treating generic question-word matches as answers. An index describes saved text, not proof that source is unchanged now.

<!-- LH-SEARCH-03 -->
Verify important conclusions against registered sources, authoritative rules, and applicable runtime evidence. Gaps, stale explanations, or contradictions can produce knowledge increments: improve explanations, sources, or aliases within authorization; for read-only requests, report recommendations. Maintain affected content only, preserve unknowns and disputes, and avoid compulsory query logs. Scanning supplies change clues; the current Agent performs semantic judgment and writing.

<!-- LH-SEARCH-04 -->
Attach stable references and useful source locations to conclusions; distinguish development facts, inference, observed operation, and deployment limits. Wiki does not create authorization rules or turn unimplemented plans into current facts. Hierarchies, cards, and tools assist investigation; validate their value through correct fresh-session task outcomes and reduced repeated exploration.
